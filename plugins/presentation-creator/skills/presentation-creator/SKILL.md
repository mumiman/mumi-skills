# Presentation Creator

สร้างเด็ค .pptx ที่เห็นแล้วรู้ว่าเป็นงานของผู้ใช้ ไม่ใช่ template กลาง ๆ หน้าตามาจากสี่สไตล์ที่ถอดจากเด็คที่ผู้ใช้ชอบ ความต่างระหว่างเด็คมาจากตัวเลือกที่ผู้ใช้เลือกตอนสั่งงานและภาพที่ผู้ใช้ใส่เอง

หลักที่อยู่เบื้องหลังทุกกติกา: **หลักฐานคือตัวสไลด์** (กราฟ ตาราง แผนภาพ ภาพถ่ายจริง) **ผู้ฟังรู้เสมอว่าอยู่ช่วงไหน** และ **สีมีความหมาย** เด็คที่ดูเป็น AI เกิดจากการตกแต่งที่ไม่มีหน้าที่ ไม่ได้เกิดจากการมีเนื้อหาแน่น

ใช้ skill นี้กับการสร้างเด็คใหม่หรือรื้อโครงเด็คเดิม ถ้าผู้ใช้แค่ให้อ่านหรือแก้ไฟล์ .pptx เดิมเล็กน้อย ให้ใช้ skill `pptx` ตรง ๆ

## ขั้นตอน

**ถามตัวเลือก → อ่านวัตถุดิบ → วางโครงเรื่อง → เขียนเนื้อหา → สร้างไฟล์ → ตรวจ → ส่งมอบ**

## 1. ถามตัวเลือก

ถามรอบเดียวก่อนเริ่มงาน ใช้เครื่องมือถามแบบตัวเลือกถ้า session มี ไม่อย่างนั้นถามเป็นข้อความ

- ข้ามข้อที่ผู้ใช้ระบุมาแล้วหรือเดาได้ชัดจากคำสั่งและเอกสารแนบ
- ถามไม่เกิน 4 ข้อ ข้อละไม่เกิน 4 ตัวเลือก วางตัวเลือกที่แนะนำไว้อันแรก
- เรียกตัวเลือกด้วยชื่อภาษาคน ไม่ใช้รหัสอย่าง A1 หรือ B2
- ตัวเลือกรองไม่ต้องถาม ให้บอกค่าที่จะใช้ในหนึ่งบรรทัด ผู้ใช้แก้ได้
- ถ้าผู้ใช้บอกว่า "เอาตามที่แนะนำ" หรือไม่อยู่ตอบ ให้เลือกค่าแนะนำ แล้วเขียนค่าที่ใช้ไว้ตอนส่งงาน

### ตัวเลือกหลัก (ถาม)

| ตัวเลือก | ทางเลือก | สิ่งที่เปลี่ยน |
|---|---|---|
| **สไตล์** | รายงานสอบสวน / ป้ายหมวด / แถบนำทาง / ป้ายเฉียง | หน้าตาทั้งเด็ค ดูหัวข้อ "สี่สไตล์" |
| **ลักษณะงาน** | Academic / Teaching / Casual | ชนิดหัวข้อ ความแน่น โครงเรื่อง ชนิดภาพ |
| **ผู้ฟัง** | ผู้บริหาร / นักวิชาการและทีมสอบสวน / เจ้าหน้าที่หน้างานหรือผู้เข้าอบรม / นักศึกษาหรือประชาชนทั่วไป | ระดับรายละเอียด ศัพท์ และสิ่งที่ต้องมีในตอนท้าย |
| **Mood & tone** | จริงจังเป็นทางการ / เป็นกันเอง / เร่งด่วนต้องตัดสินใจ / ผ่อนคลายมีอารมณ์ขัน | น้ำเสียงหัวข้อ จำนวนช่องภาพเรียกอารมณ์ การใช้สีแดง |

สไตล์ที่แนะนำตามเนื้องาน:
- **รายงานสอบสวน:** สอบสวนโรค งานวิจัยแบบ IMRaD งานที่มีกราฟและตารางมาก
- **ป้ายหมวด:** รายงานยาวที่อยากให้แต่ละช่วงมีสีของตัวเอง ผู้ฟังหลากหลาย
- **แถบนำทาง:** บรรยาย สอน journal club งานที่หัวข้อเป็นประโยคข้อสรุป
- **ป้ายเฉียง:** สอบสวนโรคหรืองานวิชาการที่อยากได้หัวสไลด์มีเหลี่ยมเฉียงและไล่สี เนื้อหามีระดับความรุนแรง (พีระมิด) หรือช่วงเวลา (ระยะฟักตัว ระยะแพร่เชื้อ)

เดาลักษณะงานจากคำสั่งได้: "conference", "thesis", "สอบสวนโรค" คือ Academic "อบรม", "สอน", "workshop", "onboarding" คือ Teaching "เล่าให้ทีมฟัง", "แชร์ประสบการณ์" คือ Casual "ผู้บริหาร", "board" คือผู้ฟังผู้บริหาร ถ้าไม่แน่ใจให้ถาม เพราะน้ำเสียงผิดงานแก้ยากกว่าหน้าตาผิด

### ตัวเลือกรอง (บอกค่าที่ใช้ ถามเมื่อผู้ใช้ขอเมนูเต็มหรือค่ามีผลมาก)

| ตัวเลือก | ค่าเริ่มต้น | ทางเลือกอื่น |
|---|---|---|
| **ชุดสี** | ตามสไตล์ | เขียวสาธารณสุข 00693E / น้ำเงินเข้ม 1F4E79 / โทนอุ่น 8F5E07 / ผู้ใช้กำหนดเอง |
| **ภาษา** | ตามภาษาของคำสั่งและเอกสาร | ไทย / อังกฤษ / ไทยปนศัพท์อังกฤษ |
| **ความยาว** | 1 สไลด์ต่อ 1-1.5 นาที | ตามจำนวนสไลด์ที่ผู้ใช้กำหนด |
| **ช่องภาพของผู้พูด** | ตาม Mood & tone | มาก / น้อย / ไม่มี |
| **Speaker notes** | มีเฉพาะคำแนะนำช่องภาพ | บทพูดเต็ม |

กติกาชุดสี: เปลี่ยนได้เฉพาะสีหลักของสไตล์ สีที่มีความหมายคงเดิมเสมอ (แดงคือจุดที่ต้องดู เทาคือบริบท) ข้อความบนพื้นสีต้องอ่านออกชัด

### ตัวเลือกแต่ละค่าเปลี่ยนอะไร

**ลักษณะงาน**
- **Academic:** หัวข้อเป็นป้ายสั้นหนึ่งบรรทัด มีบรรทัดรองบอกช่วงเวลาหรือ (N=…) ข้อสรุปอยู่ใน bullet แรกตัวหนา เนื้อหาแน่นได้ ใช้ภาพหลักฐานเท่านั้น มีเอกสารอ้างอิงและข้อจำกัด
- **Teaching:** หัวข้อเป็นประโยคข้อสรุปหรือคำถาม แบ่งเนื้อหาเป็นก้อน เปิดด้วย flowchart ภาพรวมแล้วไล่อธิบายทีละขั้น มีสไลด์ทบทวน ข้อความต่อสไลด์ไม่เกินราว 50 คำ ใช้ภาพอธิบาย
- **Casual:** หัวข้อเป็นประโยคภาษาพูด ตัวอักษรใหญ่ ข้อความน้อยที่สุด สไลด์น้อยกว่า ใช้ช่องภาพเรียกอารมณ์ได้มาก

**ผู้ฟัง**
- **ผู้บริหาร:** สไลด์แรกหลังปกคือข้อสรุปและสิ่งที่ขอให้ตัดสินใจ ไม่เกิน 8-10 สไลด์ ปิดด้วยข้อเสนอ ผู้รับผิดชอบ และกำหนดเวลา
- **นักวิชาการและทีมสอบสวน:** ใส่วิธีการ นิยาม ตัวหาร และข้อจำกัดครบ
- **หน้างานหรือผู้เข้าอบรม:** เน้นว่าต้องทำอะไร ทีละขั้น มีตัวอย่างจริง
- **นักศึกษาหรือประชาชน:** ภาษาง่าย นิยามศัพท์ทุกคำที่ใช้ครั้งแรก

**Mood & tone**
- **จริงจังเป็นทางการ:** ไม่มีช่องภาพเรียกอารมณ์ เว้นแต่ผู้ใช้ขอ
- **เป็นกันเอง:** ช่องภาพเรียกอารมณ์ไม่เกินช่วงละ 1 ช่อง
- **เร่งด่วนต้องตัดสินใจ:** ขึ้นต้นด้วยความเสี่ยงและสิ่งที่ต้องตัดสินใจ ใช้สีแดงกับความเสี่ยงหลักเท่านั้น
- **ผ่อนคลายมีอารมณ์ขัน:** ช่องภาพเรียกอารมณ์ได้ราว 1 ช่องต่อ 4-5 สไลด์ ห้ามวางคู่กับสไลด์ที่พูดถึงผู้เสียชีวิตหรือผู้ป่วยที่ระบุตัวได้

## 2. อ่านวัตถุดิบ

- อ่านเอกสารที่ผู้ใช้ให้มาทั้งหมดก่อนถามเพิ่ม ชื่อผู้แต่งและสังกัดที่อยู่ในเอกสารให้ใช้บนปกเลย
- สร้างเด็คจากสิ่งที่แหล่งข้อมูลพูด ไม่ร่างโครงทั่วไปแล้วหาข้อมูลมาเติม เพราะนั่นคือทางที่ข้อมูลแต่งขึ้นเล็ดลอดเข้ามา
- ตัวเลข วันที่ ชื่อ และข้อความอ้างอิงทุกตัวบนสไลด์ต้องชี้กลับไปที่แหล่งได้
- แยกให้ออกว่าส่วนไหนมาจากแหล่ง ส่วนไหนเป็นการเชื่อมโยงของตัวเอง ไม่นำเสนอการอนุมานเหมือนเป็นสิ่งที่แหล่งพูด
- ถ้าต้องการข้อมูลที่แหล่งไม่มี ให้ปรับโครงก่อน ถ้าไม่ได้ให้ถามผู้ใช้ ถ้าถามไม่ได้ให้เขียน `[ต้องการข้อมูล]` ไว้ในโครงและรายงานตอนส่งงาน
- ไม่มีแหล่งข้อมูล: ใช้ความรู้ทั่วไปได้ แต่ไม่แต่งตัวเลข ถ้าเป็นงาน Academic ให้บอกผู้ใช้ก่อนว่ากราฟและเอกสารอ้างอิงจะบาง
- กราฟที่วาดใหม่จากรูปในเอกสาร (ไม่มีตัวเลขดิบ) ต้องมีหมายเหตุว่าเป็นภาพประมาณจากรูปใด
- ใช้ข้อมูลตัวอย่างเมื่อใด ต้องเขียนว่า "ข้อมูลสมมติ" บนสไลด์

## 3. วางโครงเรื่อง

ร่างโครงทีละสไลด์ (หัวข้อ + หนึ่งบรรทัด) ก่อนเขียนจริงทุกครั้งที่เด็คยาวเกิน 8 สไลด์ แสดงโครงให้ผู้ใช้ดูก่อนเมื่อโครงไม่เป็นไปตามแบบมาตรฐานหรือมีทางเลือกที่ผู้ใช้ควรตัดสิน ถ้าโครงเป็นแบบมาตรฐานให้เดินต่อและบอกโครงที่ใช้สั้น ๆ

| งาน | โครง |
|---|---|
| **สอบสวนโรค / งานวิจัย** | Introduction → Method → Result → Discussion ช่วง Result เดินตามตรรกะการสอบสวน: บริบท → ขนาด → timeline → ความเชื่อมโยง → epidemic curve → ลักษณะผู้ป่วย → ปัจจัยเสี่ยง → analytic → มาตรการที่ทำ แล้วปิดด้วย limitation, recommendation, conclusion |
| **Teaching** | เป้าหมายการเรียน → flowchart ภาพรวม → ทีละก้อน (แนะนำ ยกตัวอย่าง ทบทวน) → ตัวอย่างจริง → สรุปและแหล่งเรียนต่อ |
| **ผู้บริหาร** | ข้อสรุปและสิ่งที่ขอ → บริบทเท่าที่จำเป็น → ข้อค้นพบ → ทางเลือก → ความเสี่ยง → ขั้นถัดไป |
| **อธิบายให้ผู้ฟังทั่วไป** | เปิดด้วยคำถามหรือข้อเท็จจริงที่น่าแปลกใจ → คืออะไร → ทำงานอย่างไร → ทำไมสำคัญ → ตัวอย่าง → สิ่งที่อยากให้จำ |
| **Casual / เล่าเรื่อง** | เปิดด้วยเรื่องหรือคำถาม → ประเด็นทีละข้อ → สิ่งที่อยากให้จำ |
| **Pitch** | วิสัยทัศน์ → ปัญหา → ทางแก้ → ทำไมต้องตอนนี้ → ขนาดโอกาส → ตัวงาน → หลักฐานความคืบหน้า → รูปแบบการเงิน → ทีม → สิ่งที่ขอ |
| **งานอื่น** | ถามผู้ฟัง น้ำเสียง และโครงที่ต้องการ ถ้าผู้ใช้ไม่มี ให้เสนอโครงแล้วปรับ |

กติกาโครงที่ใช้ทุกงาน:
- เนื้อหาที่เป็นกระบวนการ ให้มีสไลด์ flowchart ภาพรวมก่อน แล้วไล่อธิบายทีละขั้นตามลำดับเดียวกับ flowchart
- ตัวนำทางบอกช่วงต้องตรงกับช่วงจริงของสไลด์นั้น ชื่อช่วงตั้งตามโครงของเด็ค ไม่จำเป็นต้องเป็น IMRaD
- เด็คที่ใช้แหล่งข้อมูลภายนอกต้องมีสไลด์แหล่งข้อมูลท้ายเด็ค

## 4. เขียนเนื้อหา

**หัวข้อ**
- สามชั้น: คำบอกหมวด ("Result:", "Timeline:") → หัวข้อ → บรรทัดรอง (ช่วงเวลา กลุ่มย่อย หรือ N)
- Academic ใช้ป้ายสั้นหนึ่งบรรทัด Teaching และ Casual ใช้ประโยคข้อสรุปไม่เกินสองบรรทัด
- ไม่ใช้หัวข้อกลวงอย่าง "ภาพรวม" หรือ "บทนำ" โดยไม่มีเนื้อหาต่อท้าย

**ข้อความ**
- bullet แรกคือข้อค้นพบหลัก ขึ้นต้นด้วยตัวเลขหรือวลีตัวหนา ("ผู้ป่วย 66 ราย")
- Discussion: ข้ออ้างตัวหนา แล้วตามด้วยหลักฐานในข้อย่อย เอกสารอ้างอิงเป็นเลขยกและรายการตัวเล็กมุมล่าง
- เน้นคำสำคัญในประโยคด้วยตัวหนาบวกสี ไม่เกิน 1-2 จุดต่อ bullet
- ศัพท์เทคนิคภาษาอังกฤษคงไว้ได้ในประโยคไทย

**ความซื่อตรงของข้อมูล**
- ข้อมูลไม่ครบต้องบอกที่มุมล่างของสไลด์นั้น ("จากผู้ตอบ 68/146 ราย, 47%")
- แหล่งที่มาของตัวหารใส่เป็นหมายเหตุดอกจัน
- ตรวจผลรวมและร้อยละทุกตัวด้วยการคำนวณจริงก่อนวางลงสไลด์

## กติกา visualization

- **Epidemic curve:** แท่งชิดกัน แยกชนิดผู้ป่วยด้วยแท่งทึบกับแท่งโปร่งขอบสีเดียวกัน ใส่เหตุการณ์เป็นลูกศรชี้ลงพร้อมป้าย สีลูกศรตามผู้กระทำ (แดงคือเหตุการณ์เสี่ยง เขียวคือการตอบโต้ของทีม) แถบเหตุการณ์และแถบมาตรการอยู่ใต้แกนเวลา มีหมายเหตุบอกวิธีนับวัน
- **กราฟแท่งเปรียบเทียบ:** เน้นแท่งเดียวด้วยสี ที่เหลือเป็นเทา ตัวเลขอยู่ในแท่งตัวหนา แกนร้อยละอยู่ด้านบนสำหรับแท่งแนวนอน
- **กรอบขยาย:** เมื่อแท่งหนึ่งมีรายละเอียดย่อย โยงเส้นจากปลายแท่งไปกรอบที่มีกราฟย่อย ใช้สีเดียวกับแท่งแม่ และบอก n ของกราฟย่อย
- **เส้นอ้างอิง:** เป้าหมายหรือเกณฑ์วาดเป็นเส้นพร้อมป้าย เมื่อเทียบหลายระดับใช้สเกลเดียวกัน
- **แผนภาพจุด:** หนึ่งจุดคือหนึ่งคน รูปทรงบอกประเภทคน สีบอกสถานะ พื้นสีอ่อนบอกกลุ่มที่สัมผัสร่วมกัน มีคำอธิบายสัญลักษณ์ และบอก "1 จุด = 1 ราย" ในบรรทัดรอง
- **แผนผังข้อมูล:** กล่องขาวขอบดำ ลูกศรบาง กล่องผลลัพธ์เป็นตัวหนา พื้นสีอ่อนล้อมกลุ่มพร้อมป้ายชื่อกลุ่มในเครื่องหมายคำพูด รายการที่ตัดออกเขียนไว้ข้างลูกศร
- **ตาราง:** แถวหัวพื้นเทา เส้นบางสีเทาอ่อน คอลัมน์แรกชิดขวา แถวที่ต้องดูเป็นตัวแดงหนา
- **พีระมิดระดับความรุนแรง (ยอดภูเขาน้ำแข็ง):** ใช้เมื่อข้อมูลเป็นชั้นที่ซ้อนกันจากมากไปน้อย เช่น ไม่ป่วย → อาการน้อย → พบแพทย์ → นอนโรงพยาบาล → เสียชีวิต วาดเป็นรูปหลายเหลี่ยมชั้นละชิ้นจากเส้นกลางเดียวกัน ความกว้างครึ่งหนึ่งของแต่ละระดับเท่ากับ 0.57 × ระยะจากยอด เว้นช่องระหว่างชั้น 0.035 ยอดสีเข้มสุด ไล่ลงไปสีอ่อน ชั้นล่างสุดคือส่วนที่ระบบเฝ้าระวังมองไม่เห็น (ไม่มีอาการ ไม่มาพบแพทย์) ใช้สีทรายอ่อนต่างโทนและเว้นช่องห่างกว่า 0.1 เหมือนเส้นผิวน้ำ วางสี่เหลี่ยมสีขาวโปร่ง 40% ทับซีกขวาของส่วนเหนือน้ำ ป้ายอยู่ซ้ายของแต่ละชั้น บรรทัดแรกเป็นร้อยละและจำนวนตัวหนา บรรทัดสองเป็นชื่อชั้น ป้ายชั้นใต้น้ำอยู่ในตัวชั้น ความสูงของชั้นเรียงตามลำดับขนาด ไม่ต้องตรงสัดส่วน แต่ต้องบอกตัวหารของร้อยละในหมายเหตุ และชั้นใต้น้ำต้องมีตัวเลขจากข้อมูลจริงหรืออ้างอิง ถ้าไม่มีให้เขียนว่า "ไม่ทราบจำนวน" คู่กับกราฟแท่งแนวนอนของอาการด้านขวาได้
- **สเกลช่วงเวลา (duration scale):** ใช้กับระยะฟักตัว ระยะแพร่เชื้อ ระยะเวลาป่วย หรือระยะกักตัว แถวช่องเท่ากันเรียงแนวนอน ช่องละหนึ่งหน่วยเวลา มีตัวเลขในช่อง สีสามระดับจากสีเดียว: อ่อนคือพิสัย กลางคือ IQR เข้มตัวขาวคือมัธยฐาน มีสามเหลี่ยมเล็กชี้เข้าสเกลทางซ้าย และบรรทัดเทา 12pt ใต้สเกลบอกหน่วยกับความหมายของสี เหนือสเกลมีค่าสรุปเป็นข้อความ (มัธยฐาน IQR พิสัย) ค่าที่เกินปลายสเกลให้บอกในข้อความ
- **เส้นช่วงเวลาของเหตุการณ์:** เส้นเทาแนวนอน มีวงกลมขนาด 0.4 เป็นจุดเหตุการณ์ (ขอบทึบคือเหตุการณ์ที่ทราบวันแน่นอน ขอบจุดไข่ปลาคือประมาณการ) แถบสีอ่อนสูง 0.4 คลุมช่วงที่สนใจ เช่น ช่วงแพร่เชื้อ ป้ายอยู่ใต้จุดและใต้แถบ วางใต้สเกลช่วงเวลาโดยใช้แกนเวลาเดียวกันเมื่อหน่วยตรงกัน
- **สัดส่วนเดียว:** ใช้แท่ง 100% แท่งเดียวหรือวงแหวนที่มีสีเพียงส่วนเดียว พร้อมตัวเลขตัวหนาข้าง ๆ
- ทุกกราฟ: ไม่มีกรอบ เส้นกริดเทาอ่อน ไม่มีชื่อกราฟซ้ำกับหัวข้อสไลด์ ป้ายแกนและป้ายข้อมูลหน้าตาเดียวกันทั้งเด็ค

## ช่องภาพของผู้พูด

ผู้ใช้เลือกภาพเอง (textbook งานวิจัย meme ภาพถ่ายภาคสนาม) เพื่อคุมอารมณ์ผู้ฟัง skill มีหน้าที่ออกแบบช่องรอไว้ ไม่ใส่ภาพ stock หรือภาพที่สร้างขึ้นเอง เว้นแต่ผู้ใช้ขอ ถ้าผู้ใช้แนบภาพมา ให้ใส่ลงช่องที่ตรงหน้าที่

| ชนิดช่อง | พฤติกรรม | ข้อความในช่อง (ต้องขึ้นต้นตามนี้) |
|---|---|---|
| **ภาพหลักฐาน/อธิบาย** | แสดงเต็มภาพ ไม่ตัดขอบ | `ภาพหลักฐาน/อธิบาย: …` |
| **ภาพเรียกอารมณ์** | ขยายเต็มกรอบ ตัดขอบ | `ภาพเรียกอารมณ์: …` |
| **ภาพถ่ายภาคสนาม** | ขยายเต็มกรอบ ตัดขอบ | `ภาพถ่ายภาคสนาม: …` |
| **ภาพปก** | ขยายเต็มกรอบ ใส่คำว่า "วงกลม" ถ้าเป็นช่องวงกลม | `ภาพปก: …` หรือ `ภาพปกวงกลม: …` |
| **โลโก้** | แสดงเต็มภาพ | `โลโก้หน่วยงาน: …` |

- ทุกช่องมีพื้นสีอ่อนรองอยู่ใน layout เพื่อให้สไลด์ยังดูสมบูรณ์เมื่อยังไม่มีภาพ
- ช่องภาพหลักฐานและภาพเรียกอารมณ์มีบรรทัดแหล่งที่มาคู่กันเสมอ (`แหล่งที่มาของภาพ: …`)
- เขียนใน speaker notes ของสไลด์นั้นว่าช่องนี้ควรได้ภาพแบบไหนและทำหน้าที่อะไร
- ไม่เขียนข้อความแบบ `[IMAGE: …]` ลงบนสไลด์

## ฟอนต์

- ใช้ **Sarabun** ตัวเดียวทั้งเด็ค ทั้งไทยและอังกฤษ ตั้งที่ธีมที่เดียว ไม่ระบุชื่อฟอนต์รายชิ้น
- รายชื่อฟอนต์ที่อนุญาต: Sarabun และ Arial (เฉพาะเป็นฟอนต์ของจุด bullet ในต้นแบบ) รายชื่อนี้ยังไม่ได้ยืนยันกับเครื่องของผู้ใช้ ถ้า session เข้าถึงเครื่องผู้ใช้ได้และผู้ใช้อนุญาต ให้อ่านรายชื่อฟอนต์จาก `~/Library/Fonts` และ `/Library/Fonts` มาเทียบ
- ติดตั้ง Sarabun ในที่ที่สร้างไฟล์ก่อน render ตรวจงาน (ดาวน์โหลดจาก `https://raw.githubusercontent.com/google/fonts/main/ofl/sarabun/Sarabun-Regular.ttf` และ Bold, Italic, BoldItalic) ไม่อย่างนั้นการตรวจข้อความล้นกรอบจะผิด
- ผู้ใช้ขอฟอนต์อื่นได้ แต่ต้องบอกว่ายังไม่ได้ยืนยันว่าเครื่องมี

## 5. สร้างไฟล์

โหลด skill `pptx` แล้วสร้างแบบ structured deck ด้วย pptxgenjs ตามที่ skill นั้นกำหนด (ธีม, layout, placeholder, section, `applyTheme`) สเปกสไตล์ในไฟล์นี้มีน้ำหนักเหนือคำแนะนำด้านดีไซน์ทั่วไปของ `pptx` เพราะเป็นสไตล์ที่ผู้ใช้เลือกแล้ว รวมถึงแถบหัวของสไตล์ป้ายหมวด หัวเฉียงไล่สีของสไตล์ป้ายเฉียง และเส้นคั่นบนปกของสไตล์รายงานสอบสวน

ข้อที่ต้องทำให้ถูก (ทดสอบแล้วกับ pptxgenjs):

- **ช่องภาพ:** ประกาศเป็น placeholder ชนิด `image` ใน layout วางหลังสี่เหลี่ยมพื้นสีอ่อนของมัน pptxgenjs จะใส่ placeholder ว่างลงสไลด์ให้เอง แล้วสคริปต์ด้านล่างจะแปลงชนิดตามข้อความขึ้นต้น
- **ย่อหน้าหลายสี:** ใส่ตัวเลือกระดับย่อหน้า (`bullet`, `indentLevel`, `paraSpaceAfter`) ที่ run แรกของย่อหน้าเท่านั้น และ `breakLine` ที่ run สุดท้าย
- **ภาษาไทย:** ใส่ `lang: 'th-TH'` ให้ run ที่มีอักษรไทย
- **ตาราง:** `margin` ของเซลล์เป็นนิ้ว (เช่น `[0, 0.1, 0, 0.1]`) ใส่ `fontFace: '+mn-lt'`
- **กราฟ:** ใส่ `'+mn-lt'` ให้ทุกตัวเลือก `*FontFace` กำหนด `layout: {x, y, w, h}` ของพื้นที่วาดเอง เพื่อคำนวณตำแหน่งลูกศรและป้ายได้: จุดกลางแท่งที่ i คือ `chart.x + layout.x·chart.w + (i+0.5)/n · layout.w·chart.w` และความสูงของค่า v คือ `chart.y + layout.y·chart.h + (1 − v/max) · layout.h·chart.h`
- **Epidemic curve:** `barGapWidthPct: 3` (ค่า 0 ถูกเมิน) แท่งโปร่งใช้ `chartColors: [สีหลัก, 'FFFFFF']` กับ `dataBorder`
- **แท่งแนวนอน:** `catAxisOrientation: 'maxMin'` เน้นแท่งเดียวด้วย `chartColors` หลายค่าเป็น hex ป้ายค่าใช้ `dataLabelPosition: 'inBase'`
- **ไอคอน:** render จาก react-icons เป็น PNG สีดำ
- **รูปหลายเหลี่ยม (หัวเฉียง พีระมิด):** ใช้ `shape: pres.ShapeType.custGeom` พร้อม `points: [{x, y}, …, {close: true}]` โดยพิกัดจุดนับจากมุมซ้ายบนของกรอบรูปนั้นเอง และ `x, y, w, h` คือกรอบที่ครอบทุกจุด ใน layout เขียนเป็น `{ text: { text: '', options: {…} } }` บนสไลด์ใช้ `addShape`
- **ไล่สี:** pptxgenjs ไม่รองรับ ให้สร้างเป็นสีทึบสีเข้มก่อน แล้วรันสคริปต์ `grad_fill.py` ด้านล่างหลัง `post_template.py` เพื่อแปลงรูปหลายเหลี่ยมใน layout ที่เป็นสีเข้มนั้นเป็นไล่สี ใช้เฉพาะป้ายหัวและบล็อกปกของสไตล์ป้ายเฉียง แล้วนับ `gradFill` ใน layout เพื่อยืนยัน

```python
"""usage: grad_fill.py deck.pptx DARK:LIGHT[,DARK:LIGHT]  e.g. 1A3B57:3476AE,613656:B579A6"""
import sys, re, zipfile, shutil
src, pairs = sys.argv[1], dict(p.upper().split(":") for p in sys.argv[2].split(","))
zin = zipfile.ZipFile(src); items = [(i, zin.read(i.filename)) for i in zin.infolist()]
def fix(m):
    sp = m.group(0)
    if "custGeom" not in sp:
        return sp
    def g(f):
        dark = f.group(1).upper()
        if dark not in pairs:
            return f.group(0)
        return ('<a:gradFill rotWithShape="1"><a:gsLst><a:gs pos="0"><a:srgbClr val="%s"/></a:gs><a:gs pos="60000"><a:srgbClr val="%s"/></a:gs>'
                '<a:gs pos="100000"><a:srgbClr val="%s"/></a:gs></a:gsLst><a:lin ang="2700000" scaled="0"/></a:gradFill>') % (pairs[dark], dark, dark)
    return re.sub(r'<a:solidFill><a:srgbClr val="([0-9A-Fa-f]{6})"\s*/></a:solidFill>', g, sp, count=1)
out = []
for i, d in items:
    if re.fullmatch(r"ppt/slideLayouts/slideLayout\d+\.xml", i.filename):
        d = re.sub(r"<p:sp>.*?</p:sp>", fix, d.decode("utf8"), flags=re.S).encode("utf8")
    out.append((i, d))
with zipfile.ZipFile(src + ".tmp", "w", zipfile.ZIP_DEFLATED) as z:
    for i, d in out:
        z.writestr(i, d)
shutil.move(src + ".tmp", src)
```

หลัง `writeFile` และ `applyTheme` ให้รันสคริปต์นี้ทุกครั้ง: `python3 post_template.py deck.pptx Sarabun`

```python
"""Thai theme font, picture-slot types, readable shape names, clean paragraph XML."""
import sys, re, zipfile, shutil, html

src, thai_font = sys.argv[1], sys.argv[2]
tmp = src + ".tmp"
zin = zipfile.ZipFile(src)
items = [(i, zin.read(i.filename)) for i in zin.infolist()]
names = {i.filename for i, _ in items}
data = {i.filename: d for i, d in items}

def layout_of(slide):
    rel = slide.replace("slides/", "slides/_rels/") + ".rels"
    m = re.search(r'slideLayouts/(slideLayout\d+\.xml)', data[rel].decode("utf8"))
    return "ppt/slideLayouts/" + m.group(1)

SP = re.compile(r"<p:sp>.*?</p:sp>", re.S)

def apply(sp, label, pic, rnd):
    sp = re.sub(r'(<p:cNvPr id="\d+" name=")[^"]*(")', lambda m: m.group(1) + html.escape(label, quote=True) + m.group(2), sp, count=1)
    if pic and 'type="pic"' not in sp:
        sp = re.sub(r'<p:ph\s+idx="(\d+)"', r'<p:ph type="pic" idx="\1"', sp, count=1)
    if rnd:
        sp = sp.replace('<a:prstGeom prst="rect">', '<a:prstGeom prst="ellipse">', 1)
    return sp

rules = {}
for n in sorted(names):
    if not re.fullmatch(r"ppt/slideLayouts/slideLayout\d+\.xml", n):
        continue
    r = {}
    def fix(m, r=r):
        sp = m.group(0)
        ph = re.search(r'<p:ph\s+idx="(\d+)"', sp)
        if not ph:
            return sp
        t = re.search(r"<a:t>([^<]*)</a:t>", sp)
        prompt = html.unescape(t.group(1)) if t else ""
        label = prompt.split(":")[0].strip()[:40] or "ช่อง"
        pic = prompt.startswith(("ภาพเรียกอารมณ์", "ภาพปก", "ภาพถ่าย"))
        r[ph.group(1)] = (label, pic, "วงกลม" in label)
        return apply(sp, *r[ph.group(1)])
    data[n] = SP.sub(fix, data[n].decode("utf8")).encode("utf8")
    rules[n] = r

for n in sorted(names):
    if not re.fullmatch(r"ppt/slides/slide\d+\.xml", n):
        continue
    r = rules[layout_of(n)]
    def fix(m, r=r):
        sp = m.group(0)
        ph = re.search(r'<p:ph\s+idx="(\d+)"', sp)
        return apply(sp, *r[ph.group(1)]) if ph and ph.group(1) in r else sp
    data[n] = SP.sub(fix, data[n].decode("utf8")).encode("utf8")

# pptxgenjs repeats <a:pPr> before every run; keep only the first in each paragraph
PARA = re.compile(r"<a:p>.*?</a:p>", re.S)
PPR = re.compile(r"<a:pPr\b[^>]*?/>|<a:pPr\b[^>]*>.*?</a:pPr>", re.S)
def clean_para(m):
    p = m.group(0)
    cut = p.find("</a:r>")
    return p if cut < 0 else p[:cut] + PPR.sub("", p[cut:])

for n in sorted(names):
    if re.fullmatch(r"ppt/(slides|slideLayouts|slideMasters)/[A-Za-z]+\d+\.xml", n):
        data[n] = PARA.sub(clean_para, data[n].decode("utf8")).encode("utf8")
    elif re.fullmatch(r"ppt/charts/chart\d+\.xml", n):
        data[n] = data[n].decode("utf8").replace('typeface="Arial"', 'typeface="+mn-lt"').encode("utf8")
    elif re.fullmatch(r"ppt/theme/theme\d+\.xml", n):
        x = data[n].decode("utf8")
        x = re.sub(r'(<a:font script="Thai" typeface=")[^"]*(")', lambda m: m.group(1) + thai_font + m.group(2), x)
        x = re.sub(r'(<a:(?:major|minor)Font><a:latin typeface="[^"]*"/><a:ea typeface="[^"]*"/><a:cs typeface=")[^"]*(")', lambda m: m.group(1) + thai_font + m.group(2), x)
        data[n] = x.encode("utf8")

with zipfile.ZipFile(tmp, "w", zipfile.ZIP_DEFLATED) as zout:
    for i, _ in items:
        zout.writestr(i, data[i.filename])
shutil.move(tmp, src)
```

หลังรันสคริปต์ ให้ยืนยันว่าช่องภาพถูกแปลงจริง: นับ `type="pic"` ใน layout และสไลด์ที่มีช่องเต็มกรอบ ถ้าได้ 0 แปลว่าข้อความขึ้นต้นของช่องไม่ตรงตามตาราง

## 6. ตรวจ

ทำครบทุกข้อก่อนส่ง:

1. **ไฟล์:** รัน `validate.py` ของ skill `pptx`
2. **ฟอนต์:** ไล่ชื่อฟอนต์ทุกตัวในไฟล์ (ธีม สไลด์ layout กราฟ) เทียบรายชื่อที่อนุญาต รายงานตัวที่หลุด ใช้ `python3 check_fonts.py deck.pptx "Sarabun,Arial"`

```python
import sys, re, zipfile, collections
path, allowed = sys.argv[1], {a.strip().lower() for a in sys.argv[2].split(",")}
z, found = zipfile.ZipFile(path), collections.Counter()
for n in z.namelist():
    if not n.endswith(".xml"):
        continue
    x = z.read(n).decode("utf8", "ignore")
    if n.startswith("ppt/theme/"):
        for blk in re.findall(r"<a:(?:major|minor)Font>.*?</a:(?:major|minor)Font>", x, re.S):
            found.update(re.findall(r'<a:(?:latin|cs) typeface="([^"]+)"', blk) + re.findall(r'<a:font script="Thai" typeface="([^"]+)"', blk))
    elif n.startswith(("ppt/slides/", "ppt/slideLayouts/", "ppt/slideMasters/", "ppt/charts/", "ppt/notesSlides/")):
        found.update(f for f in re.findall(r'<a:(?:latin|ea|cs|sym|buFont) typeface="([^"]+)"', x) if not f.startswith("+"))
print(dict(found), "| not allowed:", [f for f in found if f.lower() not in allowed] or "none")
```

3. **ภาพ:** render ทุกสไลด์แล้วดูทีละภาพ ถ้าใช้ผู้ตรวจแยกได้ให้ใช้ และบอกผู้ตรวจว่าช่องภาพว่างเป็นความตั้งใจ ให้ตรวจแทนว่าสไลด์ยังดูสมบูรณ์เมื่อไม่มีภาพ ตรวจข้อความล้น การซ้อนทับ ตัวนำทางตรงช่วง หัวข้ออยู่ตำแหน่งเดิม และสีใช้ตรงความหมาย
4. **ตัวเลข:** ทุกตัวเลขตรงกับแหล่งข้อมูล ผลรวมและร้อยละถูก สไลด์ที่ข้อมูลไม่ครบมีหมายเหตุ
5. **ช่องภาพ:** ทดสอบใส่ภาพลงช่องเต็มกรอบหนึ่งช่องด้วย python-pptx (`insert_picture`) ในไฟล์สำเนา เพื่อยืนยันว่าช่องทำงาน
